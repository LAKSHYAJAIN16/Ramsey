# Critique

The differentiator must be help during the task, not merely a floating recipe. Prove that a contextual question or equipment-aware correction saves an interruption.

The biggest delivery risk is the unverified headset loop. More features do not compensate for pairing, microphone, camera, or reconnect failures. Rehearse a short, low-risk recipe before broadening scope.

Documentation has lagged behind implementation: earlier flow notes describe gaps that later code addresses. Treat code presence, offline tests, live provider checks, and device checks as separate evidence.

Automatic step recognition is uncertain for invisible changes such as tasting or waiting. Keep user confirmation available. Visual hazard feedback must not be sold as a certified safety system.

Next proof: a user selects a recipe, asks one useful question from the Quest, completes it, and sees the correct result saved without a reset or duplicate award.
